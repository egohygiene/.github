# Contributing

Read the receiving repository's README, contribution guide and scoped agent
instructions first. Repository-local policy takes precedence over this fallback.

Route work to its durable owner using the
[organization routing guide](https://github.com/egohygiene/.github/blob/main/docs/issue-routing.md).
Search existing issues and pull requests before creating another tracker.
Describe the outcome, scope, dependencies, acceptance checks and trust boundary.
Use the [canonical authoring convention](https://github.com/egohygiene/.github/blob/main/docs/issue-authoring.md)
for issue titles, primary types and checkpoint relationships.

Keep changes focused. Explain behavior, validation and remaining limitations in
the pull request. Preserve source evidence and existing human decisions; a
passing test or merged change does not grant release, deployment or decision
approval. Run the receiving repository's own required checks and report actual
results, including failures and unavailable checks.

Never include credentials, private exports or sensitive personal data. See the
[security fallback](https://github.com/egohygiene/.github/blob/main/SECURITY.md)
for reporting a suspected vulnerability. Licensing and contribution attestations
remain repository-specific; this file introduces no license, CLA or signing rule.
